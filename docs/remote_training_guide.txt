GraphNLI-AXb - Guia de treinamento remoto
==========================================

Este guia descreve como acessar a maquina NVIDIA, preparar o projeto,
executar o experimento em segundo plano e monitorar os logs e a GPU.

1. Conectar por SSH
-------------------

Primeiro, conecte a VPN da universidade. Depois, no terminal local:

    ssh -o IdentitiesOnly=yes \
      -i ~/.ssh/id_ed25519 \
      antoniosrn@192.168.37.52

O acesso usa a chave SSH cadastrada pelo DTI. A senha do usuario nao e usada
no login SSH.

2. Atualizar o repositorio
--------------------------

Na maquina remota:

    cd ~/GraphNLI-AXb
    git pull --rebase origin main

3. Preparar o ambiente Python
-----------------------------

O projeto exige Python >= 3.11 e < 3.13. O Poetry deve estar no PATH:

    export PATH="$HOME/.local/bin:$PATH"
    poetry --version

Instale as dependencias principais. O grupo wiktionary-dump pode ser
omitido quando os caches ja estiverem prontos:

    poetry config virtualenvs.in-project true
    poetry install --without wiktionary-dump

4. Corrigir a compatibilidade CUDA, se necessario
--------------------------------------------------

A GTX 1080 Ti desta maquina usa um driver compativel com CUDA 12.2. Se o
PyTorch instalado informar que o driver e antigo, verifique:

    poetry run python -c \
      "import torch; print(torch.__version__); print(torch.version.cuda)"

Uma versao compativel pode ser instalada assim:

    poetry run pip install --force-reinstall \
      --index-url https://download.pytorch.org/whl/cu121 \
      torch==2.5.1

Teste a GPU:

    poetry run python -c \
      "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"

O resultado esperado e True e NVIDIA GeForce GTX 1080 Ti.

5. Preparar os datasets
-----------------------

Para o pipeline portugues:

    poetry run python scripts/download_portuguese_nli.py

Para AX-b, XNLI e MNLI:

    poetry run python scripts/download_datasets.py --with-optional

Para SICK:

    poetry run python scripts/download_sick.py

6. Conferir o YAML
------------------

O pipeline remoto deve usar CUDA. Em configs/experiment_0001.yaml, o
pipeline portugues deve conter:

    portuguese:
      device: cuda
      batch_size: 64

O batch size 64 pode causar CUDA out of memory nas arquiteturas com grafos.
Se isso acontecer, reduza para 4 ou 2 e execute novamente.

7. Iniciar o treinamento com tmux
---------------------------------

Crie uma sessao persistente:

    cd ~/GraphNLI-AXb
    mkdir -p logs
    tmux new -s experiment0001

Dentro da sessao, execute:

    poetry run graphnli-pipeline configs/experiment_0001.yaml 2>&1 | \
      tee logs/experiment_0001.log

8. Sair sem interromper
-----------------------

Para sair da sessao mantendo o treinamento ativo:

    Ctrl+B
    D

Isto faz o detach do tmux. Nao use Ctrl+C para sair, pois Ctrl+C interrompe
o processo de treinamento.

Para verificar as sessoes existentes:

    tmux ls

Para voltar a acompanhar a sessao:

    tmux attach -t experiment0001

9. Monitorar logs e GPU
-----------------------

Em outra conexao SSH, acompanhe os logs:

    cd ~/GraphNLI-AXb
    tail -f logs/experiment_0001.log

Para monitorar a GPU:

    watch -n 1 nvidia-smi

O comando mostra VRAM usada, utilizacao da GPU, temperatura e processos.

Para consultar somente a memoria da GPU:

    watch -n 1 'nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu,temperature.gpu --format=csv'

10. Retomar depois de uma desconexao
-------------------------------------

Se a conexao SSH cair, reconecte e execute:

    cd ~/GraphNLI-AXb
    tmux attach -t experiment0001

O processo continua dentro do tmux. No pipeline YAML, resultados que ja
possuem result.json sao ignorados. O Optuna continua usando o optuna.db
persistente e executa somente os trials restantes.

11. Interromper o treinamento
-----------------------------

Entre na sessao:

    tmux attach -t experiment0001

Interrompa o processo:

    Ctrl+C

Depois, feche a sessao:

    exit

Os resultados ja salvos permanecem em:

    runs/experiment_0001/

Para executar novamente, use o mesmo YAML. O pipeline reaproveita os estudos
do Optuna e as combinacoes de modelo/seed que ja tenham result.json.
